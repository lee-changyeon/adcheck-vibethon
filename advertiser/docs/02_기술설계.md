# 기술 설계 — 애드체크 비즈 (광고주용)

## 1. 구성
```
sns-ma/
├─ src/            ← 크리에이터용 애드체크 (원본 점검 규칙 src/data/rules.ts)
├─ advertiser/     ← 광고주용 애드체크 비즈 (별도 Vite 앱, 별도 배포)
│  ├─ src/data/rules.ts, types.ts  ← 원본 복사본 (npm run sync-rules)
│  ├─ docs/        ← 광고주용 문서·프롬프트 기록
│  ├─ .claude/     ← 이 폴더 전용 훅(프롬프트 기록·종료 시 검사)·미리보기 설정
│  └─ CLAUDE.md    ← 이 폴더 전용 작업 규칙
└─ docs/           ← 크리에이터용 문서
```
- 기술 스택은 크리에이터용과 같음 (Vite + React 19 + TS + Tailwind v4 + recharts) + **tesseract.js 7.0.0** (카메라 스캔 OCR)
- tesseract.js 설치로 이 폴더에 자체 `node_modules`가 있음
- 대표 색: 청록(brand-600 `#0f766e`) — 크리에이터용(남색)과 한눈에 구분
- 배포: `advertiser` 폴더에서 `npm run deploy` (Vercel 프로젝트 `adcheck-biz-vibethon`)

## 2. 데이터 구조
```ts
// advertiser/src/data/biz.ts
type Campaign = { id: string; name: string; brand: string; reward: Exclude<Reward, 'none'>; createdAt: string }
type ActionStatus = 'open' | 'requested' | 'resolved'   // 미조치 · 수정 요청함 · 확인 완료
type Post = {
  id: string; campaignId: string
  influencer: string          // @계정
  platform: Platform
  text: string                // 현재 게시물 글 (수정본을 붙여넣으면 교체)
  status: ActionStatus
  updatedAt: string
}
```
- 판정·점수·문제 항목은 저장하지 않고 `runCheck({ platform, reward: campaign.reward, brand: campaign.brand, text })`로 매번 계산
- 판정이 "적합"이면 조치 상태와 무관하게 조치 필요 없음으로 본다

### 협업 기능 (advertiser/src/data/collab.ts)
```ts
type Creator = { id; name; field: CreatorField; followers: number; accounts: { kind: 'instagram'|'youtube'|'blog'|'tiktok'; handle }[]; contact; memo; createdAt }
type CollabEvent = { id; name; startsAt; place; description; capacity: number; deadline; closedManually: boolean; template: string; createdAt }
type DmRecord = { id; eventId; creatorId; creatorName; to; message; sentAt; status: 'sent'|'read'|'failed' }
type Application = { id; eventId; creatorId: string | null; name; handle; appliedAt /* ISO, 밀리초까지 */ }
```
- 저장 키: `adcheckbiz.creators`, `adcheckbiz.events`, `adcheckbiz.dms`, `adcheckbiz.applications` (`useCollab` 훅). 샘플은 `collabSample.ts`, 행사 날짜는 처음 열 때 시각 기준으로 잡음
- **선발/대기는 저장하지 않고 계산:** `rankApplications(apps, capacity)` — 신청 시각 오름차순, 앞에서 capacity명 '선발', 나머지 '대기 n'. 그래서 취소하면 대기 1번이 자동으로 선발됨
- **마감:** `isClosed = closedManually || 지금 ≥ deadline`. 마감이면 신청 추가 함수가 막고 버튼도 숨김
- **DM 템플릿:** `{이름}·{계정}·{분야}·{행사명}·{일시}·{장소}·{내용}·{모집인원}·{마감}`을 `fillTemplate`가 사람별로 치환. 보낼 계정은 인스타 → 틱톡 → 유튜브 → 블로그 순으로 첫 계정. 계정이 없으면 상태 'failed'
- 실제 SNS DM API는 쓰지 않음 (인스타그램 DM API는 비즈니스 계정·앱 심사가 필요). 발송은 기록만 남기고, 실제 발송은 문구 복사로
- 화면 이동 직전 저장(`saveNow`): 행사를 만들고 바로 상세 화면으로 넘어갈 때 저장이 끝나기 전에 화면이 닫히지 않도록

## 4. 화면 스캔 파이프라인
```
입력 3가지                         장면 고르기 (src/lib/frames.ts)                      글자 읽기 (src/lib/ocr.ts)            등록
─────────────                      ─────────────────────────────                      ─────────────────────────            ─────
카메라 연속 8장 (130ms 간격) ─┐    1. 장마다 선명도 = 라플라시안 분산                  prepareForOcr: 흑백·명암 늘이기·2배   Post 추가 (useBiz.addPostNow:
사진 여러 장 불러오기 ───────┼──▶ 2. 합성본 = 선명한 상위 2/3를 위치 맞춘 뒤        ──▶ tesseract.js 'kor+eng'              이동 전에 localStorage에 바로 저장)
예시 화면 6장 (demoFrames) ──┘       픽셀별 중앙값 (장마다 바뀌는 줄무늬 제거)          cleanOcrText: 공백·'# 태그' 정리     → /posts {state: {openId}}
                                    3. 줄무늬 = 전체 중앙값 합성본과의 가로줄 밝기 차이  splitPostText: 계정 줄·좋아요·시간 제거 → 검수 시트·수정 요청 메시지
                                    4. 점수 = 선명도 ÷ (1 + (줄무늬/12)²) → 높은 순
                                    5. 1위 '추천', 합성본 '합성' 표시, 눌러서 바꾸기
```
- **줄무늬 측정**: 가로줄 평균 밝기를 그대로 보면 글줄·사진도 줄무늬로 잡힌다. 모든 장의 중앙값 합성본을 기준으로 빼면 같은 내용은 지워지고 장마다 위치가 바뀌는 깜빡임 줄무늬만 남는다. 손떨림으로 위아래가 어긋난 만큼(±6줄)은 맞춰 본 뒤 가장 작은 값을 쓴다. 기준 합성본은 작은 크기(600px)로 만들어 빠르게
- **합성 전 위치 맞추기**: 200px로 줄인 흑백 그림에서 ±5픽셀 이동 중 차이가 가장 작은 위치를 찾아 옮긴 뒤 합성 (예시 화면 OCR 일치율 36% → 81%)
- **OCR**: 처음 쓸 때만 `import('tesseract.js')`(별도 파일로 분리됨), 작업자 1개를 만들어 재사용. 한글 언어 데이터는 처음 한 번 CDN에서 받고 브라우저에 저장. 준비 90초 초과·오프라인·실패 시 한국어 오류 → 사진을 보며 직접 입력
- **카메라**: `window.isSecureContext && navigator.mediaDevices`일 때만 버튼 표시, `facingMode: 'environment'`. 촬영 후·화면을 떠날 때 모든 트랙 정지. 권한 거부(NotAllowedError)·카메라 없음(NotFoundError) 안내
- **예시 화면** (`src/lib/demoFrames.ts`): `document.fonts.ready` 후 인스타그램형 게시물(@daegu_brunch_log, 해시태그 8개 맨 끝 #협찬)을 그리고, 장마다 흐림(`ctx.filter`)·가로 줄무늬·모아레·위치 어긋남·잡음을 다르게 넣은 6장. 1장은 거의 깨끗함
- **측정 결과** (예시 6장 + 합성본, 원문 대비 글자 일치율): 추천 100%(신뢰도 90%), 합성 81%, 줄무늬 심한 장 33~97%, 많이 흐린 장 0~1%. 점수 계산 약 1초(데스크톱)
