| 한 줄 정의 | 공정위 광고 표시 기준으로 협찬 글의 뒷광고 위험을 **올리기 전(크리에이터)** 과 **올라온 뒤(광고주)** 양쪽에서 찾아 고치게 하는 모바일 웹앱 |

## 1. 문제

| 누가 | 무엇이 불편한가 | 근거 |
|---|---|---|
| 협찬을 처음 받는 대학생·소규모 크리에이터 | 업체는 "자연스럽게 올려 주세요"라고만 하고, 본인은 `#협찬`을 해시태그 맨 끝에 붙이면 된다고 생각함 → **몰라서 뒷광고** | 상위 인플루언서 광고 글 582건 중 대가를 밝힌 글 **29.9%** (한국소비자원) |
| 체험단을 운영하는 광고주(동네 가게·브랜드 마케터) | 게시물 수십 개를 하나씩 열어 표시 위치를 눈으로 확인, 수정 요청 문구를 매번 새로 작성. **광고를 맡긴 사업자도 제재 대상** | 2021~2025 공정위 모니터링 뒷광고 의심 게시물 **약 10만 9천 건** |
| 공통 | 심사지침은 길고 법률 용어라 읽지 않음. **어디에(첫 부분)·어떤 말로(한글)** 표시해야 하는지 모름 | 2024 적발 유형: **위치 39.4%, 미표시 26.5%, 표현 17.3%** (합계 83.2%) |

- 기존 방식의 한계: 공정위 점검은 **이미 올라간 글을 적발한 뒤 시정 요청**(사후). 해외 도구(FTC 기준)는 `#ad`를 정답으로 봐 한국 기준과 다르고, 고친 글을 만들어 주지 않음.

## 4. 기능 요구사항 (우선순위)

> P0 = 없으면 제품이 성립하지 않음 · P1 = 핵심 가치를 키움 · P2 = 있으면 좋음. 상태는 2026-11-17 기준.

### 4-1. 애드체크 (크리에이터용)

| ID | 우선순위 | 기능 | 요구사항 | 수용 기준 | 상태 |
|---|---|---|---|---|---|
| C-1 | **P0** | 광고 표시 점검 | 플랫폼(인스타그램·블로그·유튜브)·받은 대가·업체명·글 입력 → 6개 규칙으로 점수·판정·문제 항목("무엇이, 왜") 표시 | 예시 글(해시태그 끝 `#thanksto베이글하우스`) → **30점 위반 위험**, 문제 표현 강조 | ✅ |
| C-2 | **P0** | 고친 글 제안 | 애매·반대 표현과 해시태그 표시를 지우고 첫 줄에 `[협찬] (업체)로부터 제품을 무상으로 제공받아 작성한 글입니다.` 추가 → 복사 | 고친 글로 다시 점검하면 **100점 적합**, 원래 글로 돌아가기 | ✅ |
| C-3 | P1 | 점검 이력 | 점검할 때마다 자동 저장(최근 100개), 상세 다시 보기·삭제 | 새로고침 후에도 유지 | ✅ |
| C-4 | P1 | 통계 | 점검 수·평균 점수·통과율, **자주 틀리는 항목 차트**, 다음 글에서 지킬 한 가지 | 최다 항목을 진한 색으로 강조 | ✅ |
| C-5 | P2 | 표시 규칙 가이드 | 꼭 지킬 4가지(좋은 예·나쁜 예), 샘플 데이터 초기화 | — | ✅ |

### 4-2. 애드체크 비즈 (광고주용)

| ID | 우선순위 | 기능 | 요구사항 | 수용 기준 | 상태 |
|---|---|---|---|---|---|
| B-1 | **P0** | 캠페인 등록 | 캠페인 이름·브랜드·제공 대가를 한 번만 입력 | 게시물마다 대가를 다시 묻지 않음 | ✅ |
| B-2 | **P0** | 게시물 일괄 검수 | 계정·플랫폼·글 붙여넣기 → 즉시 판정, 필터(전체/조치 필요/문제 없음) | 크리에이터 앱과 **같은 입력이면 같은 판정** | ✅ |
| B-3 | **P0** | 수정 요청 메시지·조치 상태 | 인사·문제 항목·수정 예시·심사지침 안내가 든 메시지 생성 → 복사 시 "수정 요청함", 수정본 재검수 적합 시 "확인 완료" | 상태가 자동으로 바뀜 | ✅ |
| B-4 | P1 | 대시보드 | 게시물 수·**준수율**·조치 필요 수, 판정 분포 차트, 조치 필요 목록 | 샘플 기준 준수율 38% → 조치 후 50% | ✅ |
| B-5 | P1 | 화면 스캔 | 카메라 연속 8장(또는 사진 여러 장·예시 화면) → 선명도·줄무늬 점수로 추천 장면·합성본 → 한글 OCR → 등록·검수 | 예시 화면 추천 장면 OCR 글자 일치율 **100%** | ✅ |
| B-6 | P1 | 협업 크리에이터 DB | 이름·SNS 계정 여러 개·분야·팔로워·연락처·메모 등록·수정·삭제, 검색·분야 필터 | 샘플 10명 | ✅ (배포 전) |
| B-7 | P1 | 행사 고지 DM | 행사 만들기, 받는 사람 고르기(분야 필터·전체 선택), `{이름}`·`{행사명}` 등 템플릿, 사람별 미리보기, 발송 기록 | 계정 없으면 '발송 실패' 기록, 문구 복사 | ✅ (배포 전) |
| B-8 | P1 | 선착순 선발 | 신청 시각(밀리초) 순 정렬 → 모집 인원까지 선발·나머지 대기, 마감 시각·직접 마감, 직접 접수, 선발 명단 복사 | 취소 시 **대기 1번 자동 선발**, 마감 후 신청 막힘 | ✅ (배포 전) |

## 6. 비기능 요구사항

| 분류 | 요구사항 | 구현 방법 |
|---|---|---|
| 사용성 | 휴대폰 한 손 조작, 375px 폭, 큰 버튼, 모든 문구 한국어 | `max-w-md` 앱 틀, 하단 탭, 공통 부품(`ui.tsx`) |
| 성능 | 점검 결과 **즉시(1초 이내)** | 규칙 기반 순수 함수, 서버 왕복 없음 |
| 가용성 | 시연 중 멈추지 않음, 네트워크 없어도 점검 | 외부 API 없음, 로딩·빈 화면·오류 상태 처리, ErrorBoundary |
| 개인정보 | 공개 전 협찬 글이 기기 밖으로 나가지 않음 | 로그인·서버 저장 없음, localStorage만 사용, 사진도 브라우저 안에서 처리 |
| 일관성 | 두 앱의 판정이 절대 달라지지 않음 | 규칙 원본 1개 + `npm run sync-rules` 복사 |
| 신뢰성 | 결과가 매번 같음 (AI 생성 아님) | 결정적 규칙 엔진, 판정은 저장하지 않고 매번 계산 |
| 고지 | 법률 자문이 아님을 안내 | 점검 화면 하단 "참고용 점검" 문구 |
| 대체 경로 | 카메라·OCR 실패 시에도 진행 | https 아닐 때 카메라 숨김 → 사진 불러오기·예시 화면, OCR 90초 제한 → 직접 입력 |
| 품질 | 기능마다 타입·린트·빌드 검사 | `npm run check`, 작업 종료 훅 자동 검사, `any` 금지 |

## 8. 범위 밖 (이번 버전에서 하지 않는 것)

- 회원가입·로그인, 서버·클라우드 DB, 기기 간 동기화
- 인스타그램·블로그 계정 연동, 게시물 링크로 글 자동 가져오기 (플랫폼이 외부 수집을 막음)
- **실제 DM 발송** (외부 SNS API 없음 — 발송 기록만 남기고 문구 복사로 보냄)
- 이미지·영상 속 광고 표시 판독, 숏폼 영상 첫 장면 자막·음성 점검
- AI 문장 생성(규칙 기반으로 결과를 일정하게 유지), 법률 자문
- 크리에이터 앱 ↔ 광고주 앱 데이터 전달 (향후 링크·QR)
- 유료 결제·광고주별 옵션 (향후 광고주용 유료 운영 시)

## 9. 가정과 위험

| 위험 | 대응 |
|---|---|
| 규칙이 심사지침과 다르게 해석될 수 있음 | 결과를 "참고용"으로 고지, 향후 법률 검토 |
| 심사지침 개정 | 규칙 파일 1개만 고치면 두 앱 동시 반영 |
| 브라우저 데이터 삭제 시 이력 소실 | 1단계 로드맵: JSON 백업 |
| 흐린 사진에서 OCR 실패 | 여러 장 찍고 고르기, 직접 입력 대체 |
