배포 후 데이터(DB) 처리 — 3단계 로드맵

지금 애드체크를 그대로 배포하면 서버에 쌓이는 DB가 없습니다. 따로 처리할 데이터가 생기지 않는 구조입니다.

지금 구조: 데이터는 각자 휴대폰에만 저장

[크리에이터 휴대폰 브라우저]  ── localStorage (점검 이력, 작성 중인 글)
          ↑
[Vercel] 앱 화면 파일만 내려줌 (HTML·JS). 사용자 데이터는 받지 않음
장점단점
아직 올리지 않은 협찬 글이나 업체 정보가 밖으로 나가지 않음휴대폰을 바꾸거나 브라우저 데이터를 지우면 이력이 사라짐
회원가입·개인정보 처리방침·보관 기간 같은 개인정보 의무가 생기지 않음여러 기기에서 같은 이력을 볼 수 없음
서버·DB 비용 0원, 서버 장애가 없음운영자가 전체 이용 통계를 볼 수 없음

실제 서비스로 키운다면: 단계별 선택지

  1. 백업 파일 내보내기·불러오기 (서버 없음, 30분 안팎)
    • 이력을 파일로 저장했다가 새 휴대폰에서 불러오는 방식입니다. 이력이 사라지는 단점을 가장 싸게 줄입니다.
  2. 익명 통계만 서버에 모으기 (Vercel 서버리스 함수 + 작은 DB)
    • 글 내용은 보내지 않고 플랫폼, 대가 종류, 위반 항목 코드, 점수만 모읍니다.
  3. 로그인 + 클라우드 저장 (Supabase, Firebase 같은 서비스)
    • 여러 기기에서 이력을 함께 쓰고, 광고주용 앱과 연결할 때 필요합니다. 예를 들어 크리에이터가 점검한 결과를 광고주에게 바로 보낼 수 있습니다.
