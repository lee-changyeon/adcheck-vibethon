## 3. 자세한 설명 (4,000자)

```
협찬 글, 이대로 올려도 괜찮을까요?

애드체크는 인플루언서·블로거·유튜버가 업체에서 돈이나 제품을 받고 쓴 글을 올리기 전에, 공정거래위원회 「추천·보증 등에 관한 표시·광고 심사지침」의 표시 방법을 기준으로 광고 표시가 제대로 되어 있는지 점검해 주는 앱이에요.

■ 이렇게 써요
1. 올릴 곳(인스타그램·블로그·유튜브)과 업체에서 받은 것(원고료·무료 제품·할인 쿠폰)을 고르세요.
2. 올릴 글을 그대로 붙여넣고 [점검하기]를 누르세요.
3. 점수와 판정(적합 / 보완 필요 / 위반 위험), 문제가 된 표현과 이유를 바로 알려 드려요.
4. 규칙에 맞게 고친 글을 복사해서 그대로 올리면 끝!

■ 이런 것을 찾아 드려요
· 표시 없음: 대가를 받았는데 "광고"나 "협찬" 표시가 없어요
· 반대 표현: 협찬 글에 "내돈내산", "협찬 아님"을 썼어요
· 표시 위치: 표시가 '더보기'를 눌러야 보이는 글 끝에 있어요
· 애매한 표현: thanks to, #ad, #sponsored처럼 알아보기 어려운 말이에요
· 해시태그에 묻힘: #협찬이 해시태그 여러 개 사이에 숨어 있어요
· 대가 미기재: 무엇을 받았는지 구체적으로 적지 않았어요

■ 주요 기능
· 광고 표시 점검: 0~100점 점수와 항목별 문제 설명
· 고친 글 만들기: 첫 부분에 "[협찬] ○○로부터 제품을 무상으로 제공받아 작성한 글입니다." 같은 문장을 넣고, 애매한 표현은 지운 수정본
· 고친 글로 다시 점검: 수정본이 기준에 맞는지 바로 확인하고, 원래 글과 비교
· 점검 이력: 지금까지 점검한 글과 결과를 다시 보기
· 통계: 내가 자주 틀리는 항목을 차트로 보고, 다음 글에서 지킬 한 가지 안내
· 표시 규칙 가이드: 꼭 지킬 4가지를 좋은 예·나쁜 예로 정리

■ 내 글은 내 휴대폰에만
· 회원가입·로그인이 없어요.
· 입력한 글과 점검 기록은 휴대폰 안에만 저장되고, 어떤 서버로도 보내지 않아요.
· 점검은 휴대폰 안에서 계산되어, 한 번 연 뒤에는 인터넷이 없어도 쓸 수 있어요.
· 광고와 분석 도구를 넣지 않았어요.

■ 꼭 알아 주세요
· 점검 결과는 심사지침의 표시 방법을 바탕으로 한 참고용이며, 법률 자문이 아니에요. 최종 판단은 관련 법령과 공정거래위원회 안내를 확인해 주세요.
· 애드체크는 공정거래위원회 등 정부 기관과 관계없는 개인 개발 앱이며, 정부를 대표하지 않아요.
· 점검 기준 원문: 국가법령정보센터 「추천ㆍ보증 등에 관한 표시ㆍ광고 심사지침」 (앱의 가이드 탭에서 바로 열 수 있어요)
· 글(텍스트)만 점검해요. 사진·영상 속 표시는 점검하지 않아요.

문의: ion.adcheck@gmail.com
```

## 6. 앱 콘텐츠 (플레이 콘솔 「정책 › 앱 콘텐츠」) 응답 초안

| 항목 | 응답 | 근거 |
|---|---|---|
| 개인정보처리방침 | https://adcheck-vibethon.vercel.app/privacy | 앱 안 처리방침 화면 |
| 앱 액세스 권한 | 모든 기능을 특별한 액세스 권한 없이 이용 가능 | 로그인 없음 |
| 광고 | 광고 없음 | 광고 SDK 없음 |
| 콘텐츠 등급 (IARC 설문) | 폭력·성·욕설·약물·도박 없음, 사용자 간 소통·콘텐츠 공유 없음, 위치 공유 없음, 디지털 구매 없음 → 전체이용가 예상 | |
| 타겟층 | 18세 이상 (16~17세 추가는 선택). 13세 미만은 고르지 않음 → 가족 정책 대상 아님 | 협찬 글을 쓰는 성인 크리에이터 대상 |
| 데이터 보안 | 사용자 데이터 수집: **아니요** / 공유: **아니요** | 글·기록은 기기 localStorage에만 저장, 전송 코드 없음 |
| 정부 앱 | 아니요 | 정부 기관과 무관한 개인 앱 (앱·설명에 안내 포함) |
| 금융 기능 / 건강 / 뉴스 앱 | 해당 없음 | |

데이터 보안 설문 참고: 구글 기준으로 "기기 밖으로 전송되지 않고 기기 안에서만 처리되는 데이터"는 수집으로 보지 않는다. 호스팅(Vercel) 접속 기록은 앱 화면 파일을 내려받는 과정의 일반 웹 요청이며, 개발자가 이용자 데이터를 따로 모으지 않는다. 설문 문항이 바뀌었으면 처리방침과 어긋나지 않게 다시 확인할 것.

## 7. 다시 만들기

- 스크린샷: 개발 서버(`npm run dev`, 포트 5175)를 켜고 headless Chrome으로 360×640 화면을 3배율로 캡처했다. 캡처 스크립트는 저장소에 넣지 않았으므로(일회용), 다시 찍을 때는 Claude에게 "스토어 스크린샷 다시 찍어 줘"라고 요청한다.
- 그래픽 이미지: 같은 방법으로 1024×500 HTML(검정 `#111111` 배경 + 앱 이름·큰 제목 + 결과 화면 2장, v1.3 디자인)을 캡처했다.
- 화면 디자인이나 문구가 바뀌면 스크린샷도 다시 찍는다.
