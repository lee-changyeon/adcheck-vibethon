# 대회 이후 추진 및 개발 계획

> 발표 마지막 장과 보고서 마지막 장에 사용한다. "대회용 결과물"이 아니라 "계속 키울 서비스"로 보이게 하는 것이 목적.
> (본 대회 · 2026-11-17 작성)

## 1. 현재 상태 (대회 제출 시점)
| 앱 | 사용자 | 완성된 기능 |
|---|---|---|
| **애드체크** (크리에이터용) | 협찬 글을 올리는 인플루언서 | 광고 표시 점검(점수·판정·문제 항목), 고친 글 생성·복사·재점검, 점검 이력, 자주 틀리는 항목 통계, 표시 규칙 가이드 |
| **애드체크 비즈** (광고주용) | 체험단·협찬을 맡긴 광고주 | 캠페인 등록, 게시물 일괄 검수, 수정 요청 메시지·조치 상태, 대시보드(준수율·판정 분포), 화면 스캔(연속 촬영 → 선명한 장면 추천·합성 → 한글 OCR → 검수) |

- 두 앱은 **같은 점검 규칙 6개**(`src/data/rules.ts`)를 쓴다. 광고주용은 복사본을 `npm run sync-rules`로 맞춘다.
- **데이터 저장 방식 — 강점:** 모든 데이터는 휴대폰 브라우저의 localStorage에만 저장된다. **올리기 전 글(아직 공개되지 않은 협찬 글)이 휴대폰 밖으로 나가지 않는다.** 서버·로그인·개인정보 수집이 없어 개인정보 유출 위험이 없고, 네트워크가 없어도 점검이 즉시 된다.
- 한계:
  - 기기를 바꾸거나 브라우저 데이터를 지우면 이력이 사라진다
  - 크리에이터 앱과 광고주 앱이 서로 결과를 주고받지 못한다
  - 화면 스캔 OCR은 흐린 사진·작은 글씨에서 정확도가 떨어진다 (예시 실험: 추천 장면 100%, 많이 흐린 장 0~1%)
  - 글(텍스트)만 점검한다. 이미지·영상 속 표시, AI 가상 인플루언서 표시는 점검하지 않는다

## 2. 데이터·DB 로드맵 (3단계)
> 원칙: **필요한 만큼만, 동의를 받고, 글 원문은 가능한 한 저장하지 않는다.**

| 단계 | 목표 | 방법 | 저장하는 것 | 개인정보 보호 |
|---|---|---|---|---|
| **1단계 · 백업** | 기기를 바꿔도 이력 유지 | 서버 없이 **JSON 파일 내보내기/가져오기** (가이드·캠페인 화면에 버튼) | 사용자가 직접 가진 파일 | 서버로 아무것도 보내지 않음 (지금 방식 그대로) |
| **2단계 · 익명 통계** | "어떤 실수가 많은가" 전체 경향 파악 → 가이드·교육 개선 | **Vercel 서버리스 함수 + 작은 DB** (예: Vercel Postgres·Supabase 무료 요금) | 플랫폼, 받은 대가 종류, 문제 항목 코드, 점수, 날짜 **만** | **글 원문·업체명·계정은 절대 보내지 않음.** 첫 화면에 수집 안내, 설정에서 **끄기(opt-out)** |
| **3단계 · 로그인 + 클라우드 저장** | 여러 기기에서 이어 쓰기, 광고주 팀 공유 | **로그인 + 클라우드 DB** (예: Supabase 또는 Firebase) | 점검 결과·캠페인·조치 상태 | **개인정보 처리방침**과 **수집 동의**, **보관 기간**(예: 90일 뒤 자동 삭제), 글 원문은 **저장하지 않거나 암호화**, **탈퇴 시 즉시 삭제** |

- 2단계 통계는 대학·광고 업계에 "인플루언서가 가장 많이 틀리는 표시 유형" 자료로 공개할 수 있다 (예: 공정위 적발 유형 통계와 비교).
- 단계가 올라가도 **로그인 없이 쓰는 지금 방식은 계속 남겨 둔다.** 처음 협찬을 받는 대학생에게는 가입 없는 점검이 가장 큰 장점이기 때문이다.

## 3. 기능 발전 방향
| 분야 | 계획 |
|---|---|
| **두 앱 연결** | 크리에이터가 점검 결과(점수·판정·고친 글)를 **링크나 QR 코드로 광고주에게 전달** → 광고주 앱에서 바로 "게시 전 확인 완료"로 등록. 광고주는 캠페인 초대 링크를 보내고, 크리에이터는 애드체크로 점검한 글만 제출 (처음에는 서버 없이 링크 안에 결과를 담고, 3단계 이후 캠페인 공유) |
| **화면 스캔 OCR 개선** | 화면 기울기·원근 자동 보정, 글자 영역만 잘라 인식, 장면 여러 장의 OCR 결과를 줄 단위로 합치기, 인식 신뢰도가 낮은 글자 강조, 필요 시 서버 OCR(키는 환경변수)로 정확도 향상 |
| **AI 가상 인플루언서 표시** | 사람이 아닌 AI가 만든 가상 인플루언서의 광고는 "AI 가상 인물" 표시 여부도 점검하는 규칙 추가 (관련 지침이 나오는 대로 반영) |
| **숏폼 영상 (릴스·쇼츠·틱톡)** | 숏폼은 캡션보다 **영상 안 표시**(시작 부분 자막·음성)가 중요 → 영상 첫 장면 캡처를 화면 스캔과 같은 방식으로 읽어 "처음 몇 초 안에 협찬 표시가 있는지" 점검, 음성 안내 체크리스트 제공 |
| **규칙 갱신** | 심사지침이 바뀌면 규칙 파일 하나만 고쳐 두 앱에 동시에 반영 (지금 구조 유지) |
| **앱 형태** | 홈 화면 설치형 앱(PWA), 오프라인 첫 실행 지원 |

## 5. 기대 효과
- **크리에이터:** 몰라서 하는 뒷광고를 올리기 전에 막아 팔로워 신뢰를 지킨다
- **광고주:** 수십 개 게시물을 한 번에 검수하고 수정 요청까지 끝내 제재 위험을 줄인다
- **사회:** 공정위가 사후에 적발하는 구조(5년간 약 10만 9천 건)에 **사전 예방** 단계를 더한다

## 6. 필요한 지원
- 서버·DB 비용 (2단계까지는 무료 요금 안에서 운영 가능)
- 법률 검토: 점검 규칙과 개인정보 처리방침 자문
- 전공 연계: SNS마케팅 수업·체험단 동아리에서 시범 운영
