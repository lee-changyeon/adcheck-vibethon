# 기술 설계

## 1. 구성도
```
[휴대폰 브라우저] ── React 앱 (Vite) ── localStorage (점검 이력 저장)
                         │
                         └─ 규칙 검사 엔진 (src/data/rules.ts, 브라우저 안에서 즉시 계산)
```
외부 API·서버 없음 → 네트워크가 없어도 시연 가능.

## 2. 기술 스택
| 영역 | 사용 기술 | 선택 이유 |
|---|---|---|
| 화면 | React 19 + TypeScript | 타입 검사로 AI가 만든 코드의 오류를 빌드 단계에서 잡음 |
| 디자인 | Tailwind CSS v4 | 클래스만으로 빠르게 일관된 디자인 |
| 화면 이동 | react-router-dom | 페이지별 주소 |
| 차트 | recharts | 자주 틀린 항목 시각화 |
| 데이터 | localStorage | 서버 없이 바로 동작, 시연에 충분 |
| 배포 | Vercel | 링크 하나로 휴대폰에서 바로 시연 |

## 3. 데이터 구조
```ts
// src/data/types.ts
type Platform = 'instagram' | 'blog' | 'youtube'
type Reward = 'cash' | 'product' | 'discount' | 'none'   // 현금(원고료) · 무료 제품/서비스 · 할인/쿠폰 · 대가 없음
type Severity = 'danger' | 'warning' | 'tip'
type IssueCode = 'NO_DISCLOSURE' | 'LATE_POSITION' | 'VAGUE_WORD' | 'BURIED_HASHTAG' | 'FALSE_CLAIM' | 'NOT_SPECIFIC'
type Issue = { code: IssueCode; severity: Severity; title: string; detail: string }
type CheckInput = { platform: Platform; reward: Reward; brand: string; text: string }
type CheckResult = { score: number; verdict: '적합' | '보완 필요' | '위반 위험'; issues: Issue[]; fixedText: string }
type CheckRecord = CheckInput & { id: string; createdAt: string; score: number; verdict: Verdict; issueCodes: IssueCode[] }
```

### 점검 규칙 (공정위 「추천·보증 등에 관한 표시·광고 심사지침」 요약)
| 코드 | 판정 | 조건 |
|---|---|---|
| NO_DISCLOSURE | 🔴 위반 | 대가를 받았는데 인정되는 한글 표시(광고·협찬·유료광고·제공받아 등)가 없음. '광고'는 `[광고]`·`(광고)`·`#광고`·`광고입니다/이에요/예요/임`·`유료 광고`·`광고 포함`·`광고 글/영상/게시물/포스팅/콘텐츠`·`광고:` 모양일 때만 인정("광고 모델" 등 다른 뜻 제외) |
| FALSE_CLAIM | 🔴 위반 | 대가를 받았는데 직접 샀다·광고가 아니라고 주장: 내돈내산, #직접구매, "직접 구매했/한/해서", "제(내) 돈으로/주고 샀", "협찬·광고 아님/아니에요/아니고/없음/X", "제공·협찬·지원·대가를 받지 않았" ("직접 구매하실 분은", "광고 없는 요금제", "내돈내산 아니고/아니에요/아님/X"처럼 스스로 부정한 경우는 제외) |
| LATE_POSITION | 🔴 위반 | 표시가 첫 부분(인스타그램 첫 40자 — 이모지·결합 문자도 1자로 세는 화면 글자 기준, 블로그는 제목(첫 줄) 또는 본문 첫 줄(빈 줄 제외 두 번째 내용 줄), 유튜브는 제목(첫 줄))에 없어 '더보기'를 눌러야 보임 |
| VAGUE_WORD | 🟡 보완 | thanks to, with, #ad, #sponsored, 체험단, gifted 등 애매·외국어 표현 |
| BURIED_HASHTAG | 🟡 보완 | 표시가 해시태그로만 되어 있고 해시태그가 5개 이상이라 묻힘 |
| NOT_SPECIFIC | 💡 팁 | 표시는 있지만 받은 대가(제품 제공·원고료 등)를 구체적으로 적지 않음 |

- 점수 = 100 − 위반 35점 − 보완 15점 − 팁 5점 (최소 0)
- 판정: 위반 항목이 있으면 "위반 위험", 보완 항목이 있으면 "보완 필요", 그 외 "적합"
- 대가 없음(내돈내산)이면 표시 의무가 없으므로 적합
- 고친 글: 점검과 같은 정규식으로 애매한·반대 표현을 지운다(해시태그는 해시태그째, 표시용 #광고·#협찬도 지움 / 문장 속 표현은 그 문장째 / 문장 속 "내돈내산"은 단어만). 인스타그램은 맨 앞에 `[협찬|광고] (업체)로부터 (대가 문구) 작성한 글입니다.` 한 줄을, 블로그·유튜브는 제목 앞에 `[협찬|광고]`·제목 다음 줄에 같은 문장을 붙인다. 고친 글을 다시 점검하면 적합이어야 한다

## 4. 화면 / 파일 목록
| 화면 | 파일 | 주소 |
|---|---|---|
| 홈(대문) | src/pages/HomePage.tsx | / |
| 점검 | src/pages/CheckPage.tsx | /check |
| 이력 | src/pages/HistoryPage.tsx | /history |
| 통계 | src/pages/StatsPage.tsx | /stats |
| 가이드 | src/pages/GuidePage.tsx | /guide |
| 개인정보 처리방침 | src/pages/PrivacyPage.tsx | /privacy (하단 탭 없음) |

- 하단 탭 5개: 홈 · 점검 · 이력 · 통계 · 가이드. 상단 로고·앱 이름을 눌러도 홈으로 간다. 없는 주소는 홈으로 보낸다
- 홈은 큰 히어로(「애드체크」 두 색 글자 + 입체 일러스트 + 지금 점검하기) + 바로가기 4개 카드 + 최근 점검 카드 + 사용 3단계(`ListRow`) + 띠 배너 + 안심 안내
- 화면 디자인 v4 (v1.6): `@theme static`에 대표색 청록(brand-50~900)과 일러스트 보조색(brand-sky·sun·coral), 둥근 모서리(12·18·24·32px)와 띄움 그림자. 본문 화면 위쪽은 `PageHero`(민트 그라데이션 + 알약 라벨 `Pill` + 큰 두 색 제목 `HeroType` + 일러스트). 일러스트는 외부 이미지 없이 `src/components/Art.tsx`의 SVG(휴대폰 #광고·방패·해시태그 말풍선·돋보기·#협찬 딱지·문서·막대 그래프·책). `@theme static`은 클래스로 쓰지 않은 색 변수도 내보내게 해서 SVG의 `var(--color-brand-sun)` 등이 비지 않게 한다
- 앱 바로가기(매니페스트 `shortcuts`): 점검하기(/check), 점검 이력(/history)

- 규칙 엔진: `src/data/rules.ts` (화면과 분리, 순수 함수)
- 샘플: `src/data/sample.ts` (예시 글 3개, 이력 샘플)

## 5. 외부 연동
없음 (규칙 기반, 오프라인 동작)

## 6. 오류 최소화 전략
- 기능 하나 완성 → `npm run check` (타입 검사 + 린트 + 빌드) 통과
- 데이터 구조를 먼저 타입으로 정하고 화면을 만든다
- 외부 API를 쓰지 않아 시연 중 네트워크 오류가 없음
- 시연 전 배포본을 휴대폰에서 직접 끝까지 눌러 본다
